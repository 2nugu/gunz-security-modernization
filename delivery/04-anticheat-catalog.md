# GunZ Anti-Cheat Catalog

> **독자**: 운영자 / GM 팀 / 보안 분석가
> **목적**: GunZ 본서버 플레이 + 공개 트리 자체 빌드 테스트에서 관찰된 핵 패턴 카탈로그와 본 패키지의 탐지 매핑. 일반 FPS 안티치트 논문이 GunZ 에 그대로 적용되지 않는 이유 명시.
> **원칙**: 자동 밴 금지 — 시그널 → 경중 분류 → 운영자 리뷰. 거짓 양성의 비용이 거짓 음성보다 크다.

---

## 1. GunZ 가 일반 FPS 와 다른 점 (탐지 설계의 전제)

| 특성 | 일반 FPS (CS/Valorant) | GunZ |
|------|----------------------|------|
| 카메라 감도 | 보통 ~ 낮음 | 매우 높음 (액션 카메라) |
| 조준 위치 | 머리 우선 | **다리 우선** (공중 캐릭터의 다리 궤적이 예측 쉬움) |
| 주무기 | 라이플/권총 | **샷건 비중 높음** (스프레드 넓어 정밀 조준 무의미) |
| 이동 | 스트레이핑 | **에어 대시 / 버터링 / 슬래시 숏** — 카메라 회전이 초단위 |
| 시야 | 코너 견제 | 벽 타기/점프로 벽 위·벽 뒤 돌발 등장 |
| 시간 단위 | 초/분 | 슬래시 콤보 30~50 ms 창 |

**이 차이의 의미**: 일반 FPS 용 시그널 중 다수가 GunZ 에서 **순수 플레이 스타일 신호** 로 변질된다.

### 2.2 전투 계열 — 발사 / 명중

GunZ 본서버 플레이 중 관찰되는 **가장 흔한 핵 카테고리**. 특히 무한 강베기와 RapidFire 는 빈도가 높다.

| 핵 | 동작 | 본 패키지 탐지 | 모듈 | severity |
|----|------|---------------|------|----------|
| **무한 강베기 / InfiniteSlash** ⭐ | 슬래시 쿨다운 무시 연타. GunZ 의 시그니처 핵 | ✅ | `MCombatValidator::ValidateAttack` | Melee 450±100 ms 임계, 연속위반 승급 |
| **RapidFire (총기)** ⭐ | 무기 발사 간격 무시 | ✅ | `MCombatValidator::ValidateAttack` | 무기별 (Shotgun 1100±150, Revolver 300±80, SMG 70±30, Rifle 100±40, Rocket 1800±200) |
| **무기 쿨다운 무시 (일반)** | 모든 무기 클래스 공통 | ✅ | 위 두 항목과 통합 처리 | — |
| **AutoAim / 에임봇** | 타겟 자동 추적 | △ (통계적) | `MCombatValidator::ValidateHit` | 50발 이후 hit-rate > 95% (단독 판정 금지) |
| **온오프 에임봇** | 결정적 순간만 활성화 | ✗ | — | 미해결 (§5) |
| **ImpossibleHit** | 사거리 초과 명중 | ✅ | `MCombatValidator::ValidateHit` | 무기 range × 1.3 |
| **WeaponSpoof** | 장착 안 한 무기로 공격 | ✅ | inline ATTACK_TICK | **Novel 축**, 서버-권위 3슬롯 대조 |
| **PositionLie / PacketManipulation** | 공격자 srcPos 변조 | ✅ | inline HIT_TICK | **Novel 축**, POSITION × HIT 크로스체크 |
| **무탄핵 (탄약 무한)** | 탄창 0 무시 | ✗ | — | 서버 권위 탄창 카운트 도입 필요 |

### 2.2b 전투 계열 — 데미지 / 피격 (victim-auth 사각지대)

본 패키지의 HIT_TICK 이 **victim-authoritative** 인 점이 만드는 사각지대. **Module 13 (Damage Validator)** 이 이를 닫는다.

| 핵 | 동작 | 본 패키지 탐지 | 모듈 | severity |
|----|------|---------------|------|----------|
| **데미지 감소핵 (DamageReduce)** ⭐ | victim 이 받은 데미지를 1/N 로 보고 또는 누락 | ✅ | `MDamageValidator` ServerDamageOverride + tolerance 검증 | 보고 < 서버계산 × 0.7 → High |
| **무적핵 (Invincibility)** | victim 이 모든 HIT_TICK 차단 | ✅ | `MDamageValidator` DamageNullification (PEER_SHOT × HIT_TICK 매칭) | High |
| **체력 조작핵 (HPHack)** | victim 이 자신의 HP 직접 메모리 조작 | ✅ | `MDamageValidator` HPConsistency (HP 변화량 vs hit 합) | Critical |
| **자동 회복 / 리젠핵** | HP 가 알 수 없는 이유로 회복 | ✅ | `MDamageValidator` HPInconsistency | High |
| **데미지 증폭핵 (DamageInflate)** | 한 번 명중으로 보스급 데미지 (1-shot) | ✅ | `MDamageValidator` 보고 > 서버계산 × 1.3 | High |

#### 핵심 설계 — Server-Side Damage Override
- 클라 보고 데미지 무시. 서버가 무기 테이블 + 거리 falloff 로 계산한 값을 victim HP 에 차감
- victim HIT_TICK 은 **hit 발생 사실** 만 신뢰, **데미지 양은 서버 권위**
- 이중 보고 cross-check: 공격자 PEER_SHOT 도달 + 피해자 HIT_TICK 도달 시간차 ≤ 300 ms

#### HPConsistency — 가장 신뢰 높은 검증
```
시간 윈도우 (5초) 동안:
    sumHits     = Σ HIT_TICK.dmg
    HP_expected = HP_start - sumHits + 합법 회복
    if abs(HP_now - HP_expected) > 5: HPHack
```

상세 → [`modules/13-damage-validator.md`](./modules/13-damage-validator.md)

## 3. 금지 시그널 (오탐 위험 큼 — 구현하지 말 것)

GunZ 플레이 특성상 아래 시그널은 **순수 인간 플레이에서도 충분히 발생**. 가중치 0 또는 코드에 포함하지 않을 것:

| 시그널 | GunZ 에서 무효한 이유 |
|--------|-------------------|
| 크로스헤어 스냅 속도 (예: < 20ms 에 > 60° 회전) | 고감도 + 액션 플레이 + 슬래시 숏 패턴이 정상 |
| 헤드샷 비율 | GunZ 유저는 다리를 노림. 일반 5~10%, 프로 15% 이하. 높은 비율이 오히려 이상 |
| 샷건 정확도 | 스프레드 넓어 "정확히 겨눴는가" 무의미 |
| 단일 프레임 각도 변화 | 대시 중 카메라 자체가 회전 |
| 반응시간 (< 50 ms) | 슬래시 콤보 근육 기억으로 가능. 프로는 실제 < 50 ms 반응 가능 |

이 시그널들로 플래그를 띄우면 **프로 유저가 계속 걸린다** — 오탐 비용이 운영팀의 신뢰를 잃는다.

## 4. 검토 가치 있는 시그널 (미구현)

### 4.1 비정상적 에이밍의 지속성

핵심 아이디어 — 사람은 고속 전투 중 미세한 떨림·드리프트·과조준·보정을 보인다. 에임봇은 타겟을 잡으면 잡은 상태로 유지.

| 지표 | 설명 | 구현 난이도 |
|------|------|-----------|
| 타겟 락 지속 프레임 | 양쪽 이동 중 크로스헤어가 적 ±N px 안 유지되는 연속 프레임 | 중 |
| 슬래시 모션 중 조준 안정성 | 흔들리는 모션 프레임에서 조준이 안 흔들리면 의심 | 중 |
| 대시 후 재획득 시간 | < 50 ms + 수렴 궤적 직선·등속 | 고 |
| 마우스 마이크로 떨림 부재 | 10 Hz 이상 미세 진동 부재 | 매우 고 (입력 스트림 서버 송신 필요) |
| 조준 궤적 2차 미분 | 인간은 가속·감속·오버슈트, 봇은 smoothstep | 매우 고 |

본 패키지는 이 영역 **미구현**. 입력 스트림 서버 송신은 대역폭 부담이 크고, 클라 안티치트와의 통합이 필요.

### 4.2 조건부 정확도 (선택적 통계)

전체 명중률은 무의미하지만 **어려운 조건에서만 선택적으로 높은 명중률** 은 강력한 시그널.

| 조건 | 왜 어려운가 | 봇 vs 인간 |
|------|-----------|-----------|
| 첫 발 명중 (시야 진입 직후) | 인간은 인지·반응 시간 필요 | 봇은 즉시 락 |
| 180° 턴 직후 발사 | 카메라 관성 + 재조준 필요 | 봇은 회전 완료 프레임에 정확히 발사 |
| 공중 교차 중 원거리 샷 | 예측 어려움 | 봇은 예측선 자체를 계산 |
| 피격 직후 반격 | 피격 모션 + 집중력 분산 | 봇은 영향 없음 |

본 패키지는 이 영역 **미구현**. 매치 단위 분포 분석 + 운영자 리뷰 결합 권장.

## 5. 가장 어려운 케이스 — 온오프 에임봇

### 왜 어려운가
- 평상시는 순수 인간 플레이 → 집계 평균 정상
- 결정적 순간 (1:1 상황, 깃발 전, 라운드 끝) 에만 몇 발 활성화
- 한 매치당 "기적적인 샷" 1~2 발이면 전투 결과 뒤집기 충분

### 탐지 접근 후보 (전부 미해결)

| 접근 | 원리 | 리스크 |
|------|------|------|
| **"기적적 샷" 만 집계** | §4.1/§4.2 의 시그널을 발사 프레임 윈도우로 좁혀 개별 샷 단위 스코어링 | 정의 애매, 프로 "인생샷" 도 같은 패턴 |
| **리플레이 사후 리뷰** | 시그널 플래그 → 관리자가 의심 샷 프레임으로 점프해 육안 검토 | 운영 인력 필요. 자동 밴 금지 원칙과 정합 |
| **매치 단위 이봉(bimodal) 분석** | 한 플레이어의 샷 품질 분포가 정상 클러스터 + 이상치 클러스터 인지 | 표본 부족 시 노이즈, 수백 매치 집계 필요 |
| **장기 추세 대비 세션 이탈** | 개인 베이스라인 대비 특정 세션만 이상치 비율 급증 | 실력 향상 / 컨디션 좋음도 같은 신호 |
| **커뮤니티 리포트 가중** | 플레이어 신고를 시그널에 혼합 | 악의적 집단 리포트 위협 |

본 패키지에는 어느 접근도 구현되어 있지 않음. **운영 정책 결정 후 추가 작업** 필요.

## 6. Severity 분류 정책

```
CheatSeverity:
  Low      = 1점  (단발, 임계 근접)
  Medium   = 3점
  High     = 7점
  Critical = 10점

가중 점수 = (Low 횟수) + 3×(Med) + 7×(High) + 10×(Crit)
```

### 분류 가이드
- **Low**: 단발 위반, 측정 노이즈 가능성 있음. 거짓 양성 비율 높을 수 있음
- **Medium**: 임계의 1.5~2 배. 의도성 의심
- **High**: 임계의 2 배 이상 또는 연속 위반 누적. 운영자 우선 큐
- **Critical**: 즉시 ghost-mode 모니터링 자동 등록. WeaponSpoof 즉시 등.

### 승급 규칙 (예: `MMovementValidator`)
```
연속 위반 횟수    severity
1                 Low
3                 Medium
5                 High
10                Critical
```

리셋 조건: 정상 행동 N 분 또는 매치 종료.

## 7. 운영자 의사결정 흐름

```
시그널 발생
    │
    ▼
가중 점수 누적 (16-shard Collector)
    │
    ├── 점수 < 임계 → 로그만, 대시보드 미노출
    │
    ├── 임계 ≤ 점수 < 고임계 → 운영자 큐
    │       │
    │       ▼
    │   운영자 리뷰 (ghost-mode 모니터링 또는 리플레이)
    │       │
    │       ├── 정상 판정 → 노이즈 레이블링, 임계 튜닝 데이터
    │       └── 핵 판정 → 수동 제재 (경고 / 일시 정지 / 영구)
    │
    └── 점수 ≥ 고임계 → ghost-mode 자동 등록 + 운영자 알림
```

자동 밴 단계 없음. 모든 제재는 운영자 손을 거친다.

## 8. 향후 작업 (우선순위 순)

1. **무기 데미지 프로파일 라이브 튜닝** — Module 13 의 테이블을 회사 라이브 GunZ 무기 밸런스 표로 교체
2. **Hit zone (head/body/legs) 정밀 판정** — 부위별 multiplier 적용 (현재 Body 기본값으로 단순화)
3. **Shotgun 다중 펠릿 처리 정책** — 펠릿 단위 vs 합산 보고 결정
4. **Splash 데미지 (Rocket/Grenade)** — radius 내 victim 자동 계산
5. **BSP 지형 샘플링** — 정밀 noclip 검출 (RealSpace2 엔진 링크 선행)
6. **서버 권위 탄창 카운트** — 무탄핵 차단
7. **방향/헤딩 스푸핑 검증** — 공격자 시선 벡터 일관성
8. **맵 바운딩박스 절대 좌표 체크** — 맵 외부 이동 차단
9. **시간역행 대조** — lag-comp 통합 hit validation
10. **§4.1 에이밍 지속성 시그널** — 입력 스트림 송신 구조 결정 후
11. **§4.2 조건부 정확도** — 매치 단위 통계 인프라 구축 후
12. **온오프 에임봇 대응** — 운영 정책 결정 후
13. **클라이언트 안티치트** (별도 패키지)
